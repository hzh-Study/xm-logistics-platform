# 设计系统

适用范围：选组件库、定设计 token、配色、字体、图标。目标：视觉统一、不出「AI 味」（禁止清单见 `anti-ai-patterns.md`）。

## 规则

- MUST Web 端（货主 / 物流公司 / 管理员）用 Element Plus，司机 H5 用 Vant。理由：中文生态成熟、可主题定制，覆盖两类控件需求。
- MUST 组件库只承担基础控件（输入、选择、表格、弹层、日期等），业务布局、信息层级由项目自己写。理由：避免千篇一律的模板感。
- MUST 用自建 design token（CSS 变量）覆盖组件库默认主题；MUST NOT 直接使用库默认配色。理由：库默认色易显「模板味」，也统一跨端观感。
- MUST 单一强调色，避开默认紫 / 蓝紫；语义色仅用于状态（成功绿 / 警告橙 / 错误红）。理由：信息层级靠排版而非花哨配色。
- MUST 用系统字体栈并对中文优化（如 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`）。理由：各端原生观感，无加载负担。
- MUST 图标统一为线性风格、统一尺寸，MUST NOT 用 emoji 当图标。理由：emoji 随平台渲染不一致，显廉价。
- MUST 圆角克制（约 4–6px）、边框细、阴影轻。理由：真实业务后台的观感。
- MUST 靠字号 / 字重 / 行高建立层级。理由：排版驱动比装饰驱动更专业。

## Checklist

- [ ] Web=Element Plus、H5=Vant，库仅基础控件
- [ ] token 覆盖默认主题，单一强调色
- [ ] 系统字体 + 中文优化，线性图标无 emoji
- [ ] 克制圆角阴影，排版建立层级
