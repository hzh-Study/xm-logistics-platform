# 表单与反馈

适用范围：表单、校验、状态标签、通知 / 空 / 错状态。

## 规则

- MUST 每个输入有可见 label 且与控件正确关联（见 `accessibility.md`）。理由：可用性与可访问性。
- MUST 校验错误紧贴对应字段显示，文案说明「怎么改」，MUST NOT 只在顶部弹一个笼统错误。理由：用户能就地修正。
- MUST 用状态标签展示业务状态，文案取 `GLOSSARY.md` 术语（如「待承接」「运输中」「异常处理中」），MUST NOT 自造叫法。理由：术语一致。
- MUST 驳回 / 失败时展示后端返回的原因（`error.details`），MUST NOT 吞掉原因。理由：需求要求驳回必填原因且可见。
- MUST 关键动作（发布运输订单、取消、提交费用）有二次确认或清晰的结果反馈。理由：防误操作。
- MUST 司机不可见运费报价——界面不得渲染该字段（见 `../fastapi/security.md` 与 ADR-0007）。理由：两条资金流隔离。
- MUST 空状态与错误状态是真实业务文案，MUST NOT 用占位（见 `anti-ai-patterns.md`）。理由：不出 AI 味。

## Checklist

- [ ] label 关联，错误紧贴字段且说明改法
- [ ] 状态标签用 GLOSSARY 术语
- [ ] 驳回原因可见，关键动作有确认 / 反馈
- [ ] 司机端不渲染运费报价，空错态为真实文案
