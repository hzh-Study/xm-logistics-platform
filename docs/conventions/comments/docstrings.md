# Docstring / JSDoc

适用范围：函数、类、composable、请求函数的文档注释。保持短。

## 规则

- MUST 只在「用途无法从签名 / 名字看出」时写，且压到一行；MUST NOT 逐参数堆长篇。理由：类型注解、`response_model`、Props 类型本身已是文档，重复即噪音。
- MUST 一行说清「这是做什么的」。理由：与行内注释一致的唯一目的。
- MUST 确需说明契约时（参数单位、返回、副作用），每行一句、总共不超过几行。理由：短小。
- MUST 正文用中文，标识符 / 类型名 / `@tag` 保留英文。理由：与全仓语言策略一致。
- MUST NOT 引用「本次对话 / 之前」等会话性内容，MUST NOT 写密钥或个人信息。理由：文档要长期有效且安全。
- MUST 随签名变更同步更新。理由：防过时。

## Checklist

- [ ] 仅签名说不清时写，压到一行
- [ ] 说明「做什么」，无逐参数长篇
- [ ] 中文正文 + 英文标识符，无会话性内容 / 密钥
- [ ] 与签名同步
