# 行内说明注释

适用范围：在代码里写一句「这是什么 / 这段做什么」的说明。

## 规则

- MUST 注释紧贴被说明代码的上方，单独一行。理由：位置明确，不会指代错对象。
- MUST 单行优先，不超过约 80 字符；确实需要时才用多行，最多 3 行。理由：短小，不形成阅读负担。
- MUST 用各语言的行注释符：Python `#`、TS/Vue `//`、SQL `--`；MUST NOT 用块注释写单行。理由：跨端统一、好看。
- MUST 说明「这段代码是什么 / 做什么」，让读的人（含 AI）一眼看懂实现逻辑。理由：这是本项目注释的唯一目的。
- MUST 只在「名字说不清、逻辑不直观」时写；能靠命名表达就不写。理由：少即是多，避免噪音。
- MUST 注释随代码同变更更新。理由：过时注释比没有更糟。
- MUST NOT 写注释掉的旧代码（历史交给 git）、装饰性分隔横幅。理由：保持干净。

## Checklist

- [ ] 紧贴上方、单行 ≤80 字符、最多 3 行
- [ ] 语言注释符统一，无块注释单行
- [ ] 说清「是什么」，命名能表达处不写
- [ ] 与代码同步，无注释掉的代码 / 分隔横幅
