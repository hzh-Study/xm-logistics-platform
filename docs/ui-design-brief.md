# UI 原型 / 生图设计简报

> **给谁读**：被指派生成原型图、线框图或视觉稿的设计 agent / 生图模型。
> **读完要达到**：不看其它任何文件，就能生成一套完整、可用、风格统一的后台 + 移动端界面。
> **你要产出的东西**：下方「信息架构」列出的**全部页面**，覆盖 Web 三角色与司机 H5 两端。
> **唯一视觉方向**：现代简洁 SaaS（Linear / Vercel / Stripe 那类观感）——留白充足、单一强调色、克制圆角阴影、靠排版建立层级。

---

## 1. 这是什么产品

物流运输平台，连接**货主、物流公司、司机、平台管理员**四类主体，在同一套数据上协作完成「发布货源 → 承接 → 派单 → 执行运输 → 签收 → 费用报销」全流程。两类客户端：

- **Web 管理端**：一个登录入口，按账号身份展示对应的工作台（货主 / 物流公司 / 管理员三套界面）。桌面浏览器，左侧菜单 + 顶部栏 + 内容区。
- **司机 H5**：手机端、在微信内打开，司机一人一套界面。移动竖屏，单列卡片 + 底部操作。

两类客户端**共用一个后端 API**，业务规则只有一套。术语严格遵循 `GLOSSARY.md`，架构边界见 `docs/adr/0001`–`0008`，完整需求见 `docs/spec-v1.md`（160 条用户故事）——生成文案与状态前，先查这三处，不要自造叫法。

## 2. 四个角色（生成时据此隔离内容）

| 角色 | 客户端 | 一句话职责 | 绝不能出现的内容 |
|------|--------|-----------|-----------------|
| 货主 | Web | 发布运输订单、给出运费报价、只读跟踪进度 | 修改司机提交的打卡 / 凭证 |
| 物流公司 | Web | 承接订单、管理司机车辆、派单、处理异常、审核报销 | 竞价比价（V1 先到先得） |
| 管理员 | Web | 认证审核、禁用/恢复、异常处理、公告、车辆转籍 | 直接改写订单/任务/打卡/费用（只能追加审核与异常记录） |
| 司机 | H5 | 执行任务、打卡、装卸货、签收、提交报销 | **运费报价**（两条资金流隔离）、自行注册、抢公共货源 |

## 3. 设计系统（必须落到每一张图）

### 3.1 色彩

- **单一强调色**：品牌蓝 `#1664FF`（hover `#0E52D8`，按下 `#0A43B8`，浅底 `#EBF2FF`）。全站只此一个强调色。
- **中性色**：文字主 `#14171F` / 次 `#5B6472` / 弱 `#8A93A2`；页面底 `#F6F7F9`；卡片 `#FFFFFF`；弱填充 `#F0F2F5`；描边 `#E4E7EC`、强描边 `#D0D5DD`。
- **语义色（只用于状态，不做装饰）**：成功 `#16A34A`（浅底 `#E9F7EF`）、警告 `#D97706`（浅底 `#FEF3E2`）、错误 `#DC2626`（浅底 `#FEECEB`）。
- **禁止**：紫色 / 蓝紫渐变、渐变按钮、渐变背景、彩色玻璃拟态。信息层级靠排版和留白，不靠配色。

### 3.2 字体

- 字体栈：`Inter, -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 字号阶梯：`12 / 13 / 14 / 16 / 18 / 22 / 28 px`；字重 `400 / 500 / 600`；行高 `1.5–1.6`。
- 金额、编号、数量等数字统一右对齐 + 等宽数字（`tabular-nums`）。

### 3.3 间距 · 圆角 · 阴影 · 边框

- **间距**：4px 栅格。`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- **圆角**：控件 `6px`，卡片 `10px`，状态标签用胶囊 `999px`。克制，不要大圆角。
- **阴影**：卡片 `0 1px 3px rgba(16,24,40,.06)`；弹层 `0 12px 32px rgba(16,24,40,.12)`。轻，不要重投影。
- **边框**：`1px solid #E4E7EC`，细。

### 3.4 组件观感

- **按钮**：主按钮蓝底白字；次按钮白底描边；危险按钮红；文字按钮无框。高度 `36px`（Web）/ `44px`（H5 触控）。
- **输入框**：label 在上方或左侧，聚焦时蓝色 2px 边框 + 淡蓝光晕，错误时红框 + 字段下方红字说明「怎么改」。
- **表格**：表头浅灰底、字重 500；行高 `48px`；行 hover 浅蓝底；操作列右对齐；**不用斑马纹**；状态列用语义色胶囊标签；空态显示真实业务文案（如「暂无待承接的运输订单」）。
- **状态标签**：胶囊，浅色底 + 深色字，文字即状态字面值（见第 7 节），不要给每个状态配花哨颜色。
- **卡片 / 面板**：白底、1px 边框、10px 圆角、轻阴影；标题 16px/600，辅助信息 13px 弱色。
- **统计卡**：工作台用「数字 + 中文标签」，数字 28px/600，标签 13px 弱色，不要配大图标/花哨色块。
- **步骤条 / 时间线**：运输进度用横向步骤条（Web）或纵向时间线（H5），已完成节点蓝色、当前节点蓝色描边、未完成灰色。
- **图标**：统一线性风格、统一 20px、线条 1.5px；**禁止 emoji 当图标**。

### 3.5 布局尺寸

- **Web**：左侧菜单 `220px` 固定；顶栏 `56px`（右含角色标签 + 退出）；内容区 `max-width 1200px` 居中，页面内边距 `24–32px`，面板间距 `16–24px`。
- **H5**：按 `375px` 宽设计；单列，卡片间距 `12px`，左右留白 `16px`；主操作固定在底部通栏（≥44px 触控高），留安全区 `env(safe-area-inset-bottom)`。

## 5. 逐页规格（目标形态）

> 当前代码只是功能骨架、几乎无视觉设计。下面是**要生成的目标界面**。未列出的列表/详情子页按第 6 节通用模式套用，字段取该角色业务实体。

### 5.1 登录（Web）

- 居中单卡片（宽约 `400px`），标题「物流运输管理平台」22px/600，副标题「账号登录」13px 弱色。
- 手机号、密码（密码框带显隐切换）两个输入，主按钮「登录」通栏。
- 卡片底部一个文字按钮「注册新账号」；点开展开注册区：单选「货主 / 物流公司」+ 手机号 + 密码（≥8 位）+ 企业名称（仅物流公司显示）+ 主按钮「注册并进入」。
- 开发演示态：账号密码预填，用户只需点登录（正式上线留空）。

### 5.2 工作台首页（三个角色通用骨架）

- 顶部：页面标题「工作台」18px/600，下一行账号 · 角色 · 认证状态（弱色 13px）。
- 统计卡区：货主=仓库数/订单总数/待承接/已承接/运输中/已完成/已取消；物流公司=待审核企业/今日承接/待派单/待司机确认/运输中/已完成/异常/待审费用/司机数/车辆数；管理员=货主数/公司数/司机数/车辆数/订单总数/待承接/运输中/已完成/异常/待审认证。
- 信息区：认证状态提示面板（未通过时给出原因 + 「前往认证」链接）、最近订单 / 最近运输动态列表、系统通知列表、快捷入口（货主进仓库与订单；管理员进审核与异常）。
- 卡片化、分区清晰、真实数字；空数据用「暂无…」真实文案。

### 5.3 列表页（各角色通用，如我的订单 / 订单池 / 司机管理 / 车辆管理 / 主体查询 / 订单任务查询）

- 顶部筛选区（可折叠）：按业务字段筛选——订单按编号/状态/发布时间/发货地/收货地/货物名称；司机按姓名/认证状态/接单可用性/雇佣关系；车辆按车牌/类型/状态。筛选项用输入框 + 下拉 + 日期区间。
- 主表格：列取对应实体字段（编号、名称/货物、状态标签、时间、操作），操作列「查看 / 编辑 / 停用 / 审核」等文字按钮。
- 右上角主操作按钮（发布 / 新增 / 派单 / 创建），危险操作二次确认。
- 分页器置底右对齐；空态真实文案。

### 5.4 表单页（认证 / 发布订单 / 新增司机车辆 / 派单）

- 分区表单：用卡片把字段分组（如「基本信息」「货物信息」「发货信息」「收货信息」「运输要求」「运费报价」），每组标题 16px/600。
- 字段：label + 控件 + 帮助文字；必填项标注；校验失败紧贴字段红字说明改法。
- 底部操作栏：主按钮「提交 / 发布 / 创建」，次按钮「取消」；发布前提供确认步骤（展示全部信息摘要）。
- 发布订单尤其要体现：货物名称/类型/数量/重量/体积/包装/照片/备注；从已有仓库或临时地址选发货信息；发/收货快照只读展示；运输要求（车型/车长/载重/冷链/防雨/封闭/特殊装卸）；运费报价（固定/可议/其它 + 可议价标记）——**司机端绝不展示报价字段**。

### 5.5 详情 / 进度页（订单进度 / 任务进度）

- 上半部：单卡展示基本信息（编号、状态标签、主体、时间）。
- 中部：横向步骤条（Web）串起订单/任务状态节点，当前节点高亮。
- 下部：运输过程记录时间线（发货/到达/起运/到达收货/签收节点 + 照片缩略），只读。
- 司机 / 物流公司侧可见打卡照片；货主侧可见但只读。

### 5.6 审核 / 异常 / 费用页（管理员与物流公司）

- 待办列表 + 详情抽屉：展示提交资料 + 通过/驳回按钮；**驳回必填原因**（文本域），提交后原因作为追加记录展示。
- 费用审核：单条处理（非批量），显示费用类型/金额/时间/说明/凭证 + 关联任务，通过或驳回（必填原因）；另有「标记已支付」独立操作（记录操作人与时间）。
- 异常处理：展示异常类型、上报人、时间、现场照片，处理结果选项（继续运输 / 调整送达时间 / 更换车辆 / 更换司机 / 重新安排运输 / 终止运输），选填说明，处理后追加处理记录。
- 管理员全为只读查询 + 审核/禁用/公告/异常处置，不出现改写业务记录的按钮。

### 5.7 司机 H5 各页

- **登录**：标题「司机登录」+ 手机号/密码 + 通栏主按钮「登录」（Vant 控件，触控 ≥44px）。
- **身份绑定**：分步（1 改初始密码 → 2 身份与驾照资料 → 3 确认），顶部步骤指示，底部「下一步 / 完成」，必填校验。
- **账号阻断**：单卡说明原因（账号禁用 / 离职 / 所属公司异常），只读，无可执行操作。
- **工作台**：顶部司机姓名与所属公司；今日任务 / 待确认 / 待装货 / 运输中 / 待签收 / 待报销统计；最近记录与公司通知；大按钮「查看任务」。
- **任务列表**：卡片式（移动表格转卡片），每卡显示任务编号、货物、起运/送达地、计划时间、状态标签、操作「接单 / 查看详情」；拒绝需填原因。
- **起运/装货打卡**：地图定位区占位（不渲染真实地图）+ 定位/时间信息 + 现场照片上传 + 备注；位置异常时黄色警告条 + 必填异常说明；三阶段装货照片（装前/装中/装后）+ 「确认装货完成」；底部固定主按钮。
- **签收**：收货信息 + 现场照片 + 签收凭证上传 + 备注 + 「确认签收」。
- **异常**：异常类型单选（车辆故障/事故/封路/拥堵/货物问题/预计延误等）+ 照片 + 说明 + 提交。
- **费用提交**：单次一笔，类型（油费/过路费/停车费/维修/其它）+ 金额 + 多张凭证 + 关联任务 + 提交；列表页显示审核状态与驳回原因，可重新提交。

## 6. 通用模式（套用到所有未单列的列表/详情子页）

- **权限隔离可见性**：货主只见自己的仓库与订单；物流公司只见自己承接的订单与自有司机车辆；司机只见分派给自己的任务与相关费用；管理员平台级只读 + 审核/处置写权限。
- **资金流隔离**：运费报价是货主写在订单上给物流公司看的字段，司机界面不渲染；报销费用是司机提交给物流公司审核的另一条流，两者不混。
- **状态维度正交**：账号状态、认证状态、接单可用性、雇佣关系、车辆可用性、车辆生命周期彼此独立，界面上分开呈现，不合并成一个字段。
- **历史不可变**：业务记录只读、追加式；更正以新增记录 + 原因展示，原文保留，界面提供「查看历史」时间线。

## 7. 状态与标签字面值（必须逐字使用，来自 `spec-v1.md` / `GLOSSARY.md`）

- **认证状态**：`未提交` / `待审核` / `审核通过` / `审核不通过`。
- **账号状态**：`正常使用` / `已禁用` / `已注销`。
- **运输订单状态**：`待承接` / `已承接` / `运输中` / `已完成` / `取消处理中` / `已取消` / `异常处理中`。
- **运输任务状态**：`待司机确认` / `待装货` / `运输中` / `待签收` / `待确认完成` / `已完成` / `异常` / `已拒绝`。
- **司机接单可用性**：`可派单` / `任务占用中` / `暂停接单`；**雇佣关系**：`在职` / `离职`。
- **车辆可用性**：`可用` / `占用中` / `暂停使用`；**车辆生命周期**：`在册` / `维修中` / `已停用`。
- **费用审核状态**：`待审核` / `审核通过` / `审核不通过`；**支付状态**：`待支付` / `已支付`。
- 业务实体用 GLOSSARY 术语：运输订单、货源（待承接视图）、运输任务、发货快照、收货快照、运费报价、报销费用、打卡、异常处理记录。避免「客户/运单/订单池条目」等。

## 8. 反「AI 味」清单（出现即不合格）

- 不要紫/蓝紫渐变、渐变按钮、渐变背景、玻璃拟态。
- 不要 emoji 当图标；图标统一线性风格。
- 不要「三卡并排 + 大圆角 + 大阴影」通用模板布局，不要装饰性 blob / 网格背景 / 漂浮动画。
- 不要「欢迎使用 XX 平台」类空话标题；不要 Lorem / 示例数据 / TODO 当真实内容。
- 不要给每种状态配不同颜色造成花哨；语义色只表达状态。
- 要贴近真实业务后台的信息密度：表格、筛选、状态标签；要真实业务文案的空态/错误态；要单一强调色 + 克制圆角阴影 + 排版层级。
