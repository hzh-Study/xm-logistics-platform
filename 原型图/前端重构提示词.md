## 1. 任务目标与验收定义

### 1.1 目标

把 Web 管理端（货主 / 物流公司 / 管理员三角色共用一个入口）与司机 H5 的界面，从现有"功能骨架"重构为与 39 张原型逐页一致的界面，覆盖：

- 视觉 token（颜色、字体、字号、间距、圆角、阴影、边框、图标）；
- 组件拆分与复用；
- 交互流程与状态表现；
- 多尺寸适配与可访问性。

### 1.2 完成的定义（全部满足才算完成）

- 39 张原型页面均有对应真实页面，且逐页比对无遗漏区块、无自造字段；
- `web` 与 `driver-h5` 两端 `npm run build` 均通过（含 `vue-tsc --noEmit` 类型检查）；
- 第 15 节验收清单逐项勾选通过；
- 不产生任何后端改动、不产生任何业务层改动。

## 6. 视觉规范（token 对齐表）

### 6.1 总原则

- **单一强调色** `#1664FF`，全站唯一；禁止紫 / 蓝紫渐变、渐变按钮、渐变背景、彩色玻璃拟态。

## 7. 组件拆分与复用

### 7.1 实现规范（强制）

遵循 `docs/conventions/vue3/component.md`：

- 用 `<script setup lang="ts">`，不写 `defineComponent`；
- props / emits 用**纯类型声明** `defineProps<Props>()` / `defineEmits<{...}>()`，不得混运行时声明；
- 用 Vue 3.5 响应式解构取 props 默认值，不用 `withDefaults`；
- 组件名多词（如 `StatusPill`，不得叫 `Pill`），文件名 PascalCase 且与组件名一致，一文件一组件；
- `v-for` 配稳定 `:key`，`v-if` 与 `v-for` 不在同一元素；
- 块顺序固定：`<script setup>` → `<template>` → `<style scoped>`；
- 组件超过约 200 行或出现可复用逻辑时抽 composable；
- 样式用 `<style scoped>` + class 选择器，不在 scoped 下写裸元素选择器；全局样式只在 `App.vue` 或布局组件；
- `:deep()` / `:slotted()` 仅在必要时使用并附 `NOTE` 说明；不写用户可控 inline `:style`。

## 10. 边界情况（必须处理，不得省略）

1. **权限隔离**：货主只见自己的仓库与订单；物流公司只见自己承接的订单与自有司机车辆；司机只见分派给自己的任务与相关费用；管理员平台级只读 + 审核/禁用/公告/异常处置。路由守卫已实现，**视图层不得绕过**（例如不得用硬编码数据展示别的主体内容）。
2. **资金流隔离**：运费报价是货主写给物流公司的字段，**司机端界面绝不渲染**；报销费用是司机提交给物流公司的另一条流，二者不得混用同一组件或字段。
3. **不可变历史**：业务记录只读、追加式；更正以新增记录 + 原因展示，原文保留；界面提供「查看历史」时间线。管理员不得出现改写按钮。
4. **认证 / 账号阻断**：认证未通过时货主不能发布、物流公司不能承接与派单；账号 `已禁用` / 司机 `离职` / 所属公司异常时，司机进入 `/blocked` 且页面只读无可执行操作。
5. **首次登录**：司机首次登录强制改密 + 身份绑定三步流程，未完成不得进入工作台（守卫已实现，视图按 `h5-02` 三步骤还原）。
6. **取消申请**：只有未起运订单可申请，状态变 `取消处理中`；物流公司同意→`已取消`，驳回→恢复原状态并展示原因；运输中订单走 `异常处理中`；已完成订单不可取消。
7. **异常处理结果**：继续运输 / 调整送达时间 / 更换车辆 / 更换司机 / 重新安排运输 → 回到 `运输中`（未起运则 `已承接`）；终止运输 → `已取消` 且必填原因。所有结果追加处理记录，不覆盖原文。
8. **位置异常**：超出半径时显示黄色警告条 + 必填异常说明，**不自动拒绝打卡**。
9. **车辆转籍**：仅在车辆无进行中任务时允许审批，否则驳回并说明原因。
10. **费用审核**：审核状态与支付状态独立；单条处理，不做批量；驳回必填原因；重新提交生成新记录并关联原驳回；「标记已支付」单独操作并记录操作人与时间。
11. **拖拽 / 时间冲突**：派单时司机与车辆须属于本公司且可用，时间冲突需拦截并提示（沿用现有校验，界面按 `web-12` 抽屉展示）。
12. **加载与失败**：所有列表与详情都要有加载中、失败重试、空数据三态；失败时展示后端错误而非空白页。

## 13. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 组件文件 | PascalCase，一文件一组件 | `StatusPill.vue`，不得 `status-pill.vue` |
| 组件名 | 多词，避免与原生标签冲突 | `StatCard`，不得 `Card` |
| prop / emit | camelCase | `modelValue`、`confirmText` |
| CSS class | kebab-case，`<style scoped>` | `stat-num`、`panel-head` |
| CSS 变量 | `--<类别>-<语义>` 小写连字符 | `--color-accent-soft`、`--radius-card` |
| 路由 name | 沿用现有，不改 | `ShipperHome`、`CarrierOrderPool` |
| 视图文件 | 沿用现有文件名，不改 | `OrderPublishView.vue` |
| 图标组件 | 语义化 PascalCase | `TruckIcon.vue` 或内联 SVG |
| 文案 | 中文，术语取 GLOSSARY | `运输订单`、`发货快照`、`报销费用` |

**禁止**：把 `货源`、客户、运单、费用、报销单等 Avoid 词写进界面文案（见 `GLOSSARY.md`；`货源` 仅用于待承接视图标题，不是实体名）。
